<a id="access"></a>
## 入口与权限

管理页面为 `/manage`，使用现有 OIDC Cookie 会话。写请求继续要求固定 Origin、CSRF 和近期认证；审批、执行每次复查当前人员、自然人、授权范围、策略及目标修订。模拟身份不能代替真实多人身份或 MFA。

| 操作 | 所需角色/条件 |
| --- | --- |
| 查看版本、轮换和恢复任务 | 对应客户端 viewer |
| 提交及执行轮换/恢复申请 | 对应 requester；执行仅原申请人；至少两个其他自然人当前有效的批准 |
| 创建新的软件基础根 | 全环境 requester 及全环境审批人；客户端目标固定为 `root-management`，该 ID 不允许用于普通客户端 |
| 撤销、中止、到期收尾 | 相应 emergency_operator；根撤销和全域收尾需要全环境范围 |
| 审计查询、快照和下载 | 当前 auditor；下载还要求原导出人和近期认证，viewer 不自动获得权限 |
| 独立归档与数据库恢复核验 | 受控离线运维数据库身份和独立签名文件；不开放 HTTP 运维入口 |

模拟 demo-requester 显式配置开发 requester、viewer、emergency_operator、auditor；demo-approver-1/2 负责投票。生产人员权限仍须真实身份治理。

<a id="rotation"></a>
## 轮换

复用现有[密钥申请、交付、证明与审批接口](客户端密钥HTTP流程.md)。发起 `key_issue` 时增加：

| 字段 | 判断规则 |
| --- | --- |
| rotationOf | 字符串整数，必须是当前尚未到期 active 版本；普通首次签发留空 |
| rotationReason | 与 rotationOf 一起填写：scheduled、expiry 或 manual；原因冻结在审批清单内 |
| keyVersion | 下一个版本；客户端修订、公钥指纹和有效期仍须准确 |
| retireAt | 后续 `key_activate` 单独审批时填写 UTC 毫秒格式；有旧 active 时须晚于当前数据库时间，开发上限十五分钟 |

同一客户端最多一个开放轮换任务，期间普通签发也不能绕过任务。接收方先使用 CLI 在新的私有目录生成接收方配置，领取加密包并完成持有证明，再提交独立激活申请。

```text
issue + rotationOf -> approve -> execute -> preparing
                                  |
                             claim + proof
                                  |
activate request -> approve -> execute -> overlap
                                  |
                      deadline -> maintain -> completed
```

| 管理接口 | 用途 |
| --- | --- |
| GET /api/clients/{client}/lifecycle | 最近一百个版本、有效状态、原始有效期是否可信、退役时间、轮换任务和到期提示 |
| POST /api/lifecycle/maintain | 空 JSON 对象；全域应急权限手动收尾，权限及审计失败则不提交 |

任务状态为 preparing、overlap、completed 或 failed。任务未 completed 不表示整次轮换已经完成。旧版本有效期取原期限与批准退役期限较早值；认证始终按数据库时间拒绝，不依赖维护任务在线。迁移前历史记录的 OriginalExpiryKnown=false，表示只掌握当时保存的有效截止，不能反推原期限。

到期提示仅针对尚未到期、十五分钟内到期的 active 版本。当前提供页面待处理提示、服务内每分钟过期收尾和显式维护入口；空转不刷审计，退出跟随服务上下文。没有创建外部通知或自动执行换钥/审批操作。失败不自动恢复旧版本，也不延长过渡期限。

<a id="revocation"></a>
## 泄露撤销

POST /api/revocations 接受以下 JSON。事件 ID 是幂等身份，相同事件必须参数完全一致；重复提交返回成功，换参数返回 409。

```json
{
  "incidentId": "incident-20261019-01",
  "clientId": "backend-one",
  "keyVersion": "1",
  "rootId": "",
  "reason": "suspected_leak"
}
```

- 版本撤销：填客户端及版本，rootId 为空，只影响该版本。
- 根撤销：仅填 rootId，clientId 为空、keyVersion 为字符串 `"0"`；阻断根、隔离所有依赖客户端、撤销该根保护的版本并结束相关轮换。
- reason 固定为 suspected_leak、confirmed_leak、lost_delivery、scope_unknown。自由文本和秘密不进入原因字段。

撤销后的 compromised 是数据库保护的终态；误报也不解除原版本。撤销、修订、事件事实和审计同事务提交。认证与撤销共用域锁，提交后开始的认证拒绝；已经完成认证的外部业务操作不追溯取消。

根泄露后的恢复必须生成实际新根和新客户端秘密，不能只更换别名或重新包裹旧秘密。

<a id="recovery"></a>
## 隔离恢复

适用于已停用客户端、交付丢失或根泄露后的重新建立信任。页面支持提交恢复、查看任务和中止。客户端不需要为了换钥临时启用。

1. 应急停用客户端；如根泄露，先撤销根。无法判断是否泄露的版本按可能泄露处置。
2. 根不可用时，提交 `root_provision`，目标客户端为 root-management、expectedRevision 为字符串 `"0"`，rootId 为未使用的新 ID；其他普通客户端字段为空/零。经全环境独立多人批准后，由原申请人执行，生成进程内新软件根及独立预算。当前进程最多登记十六个根；不覆盖旧材料。
3. 提交 `recovery_issue`：除普通签发所需字段外，填写 recoveryId、incidentId、evidenceHash（64 位十六进制 SHA-256），冻结当前停用客户端修订、新版本、可信根、两把接收方公钥及期限。
4. 两人独立批准、执行、接收方一次领取并证明持有。期间客户端仍 disabled，普通签发、普通激活和新旧版本认证均不放行。
5. 读取最新修订，另行提交 `recovery_activate`，填写同一 recoveryId、incidentId、evidenceHash 和版本；不带签发字段或过渡时间。再次独立多人批准后执行。
6. 最终事务永久撤销其他所有旧版本、激活尚有效的新版本、恢复客户端、结束任务并写审计；任一检查或审计失败全部回滚。

| 接口 | 判断及下一步 |
| --- | --- |
| GET /api/clients/{client}/recoveries | 最近一百个任务及其事件、证据摘要、签发申请、版本、创建/结束时间 |
| POST /api/recoveries/{id}/abort | 空对象；应急减权，中止未完成任务，停用候选版本并保持客户端隔离；已完成任务返回冲突 |

恢复任务状态：preparing、staged、completed、aborted。领取超时或证据不再可信时中止，重新审批新方案。客户端修订变化会使旧任务交付或旧恢复票失效。

软件根只驻留当前进程。已提交根创建但材料因崩溃丢失时，不重造同名材料；核对执行记录后审批另一新根。远程结果查询和 fencing 仅预留 Provider 接口，没有装配远程执行；不会把超时自动重试为第二次签发。

<a id="audit"></a>
## 审计查询与导出

| 接口 | 行为 |
| --- | --- |
| POST /api/audit/query | Cookie + Origin + CSRF；最多一百行，按 sequence 继续查询，每次复查权限 |
| POST /api/audit/exports | 近期认证；物化白名单 JSONL 快照，最多五千行/8 MiB；超限返回冲突，不悄悄截断 |
| GET /api/audit/exports | 原申请人当前有权限的最近一百个导出任务，包括冻结筛选、条数、摘要、创建/过期时间 |
| GET /api/audit/exports/{id} | 原申请人、当前范围 auditor、近期认证及期限均通过才下载，并写审计；下载 ID 不是权限凭据 |
| GET /api/audit/auth-failures | 全环境 auditor 查看最近二十四小时的固定原因分钟聚合，不按未验证客户端建维度 |

查询与导出请求字段如下，省略的字符串筛选表示不限定：

```json
{
  "clientId": "backend-one",
  "action": "client_auth",
  "result": "authenticated",
  "requestId": "",
  "targetId": "",
  "after": "0",
  "limit": 100,
  "from": "2026-10-19T00:00:00Z",
  "until": "2026-10-20T00:00:00Z"
}
```

时间范围左闭右开，最多三十一天。after 是字符串序号；快照导出必须为 `"0"`。clientId 留空要求全环境 auditor，局部授权不能据此查看全域或全域根事件。

导出返回 ready，十分钟后 expired；每人最多十个、每域最多一百个未过期任务。创建新导出会清除该域过期载荷并删除超过一天的过期任务元数据，永久审计事件不因此删除。下载响应为 application/x-ndjson，没有 CSV 公式执行入口。

白名单只包含事件 ID、序号、环境/客户端、请求 ID、操作身份、操作、对象、结果和数据库记录时间；不导出密钥、token、Cookie、接收方私钥、签名/MAC 或交付包。版本和审批详情通过相应申请/对象关联查看，不在审计行拼入整份敏感请求。数据库记录时间不等于精确提交时刻。

认证成功与 nonce 消费、审计和 outbox 同事务，留痕失败即拒绝。HTTP 审计使用服务端 trace ID；直接库调用无 HTTP trace 时使用已验签请求 ID。认证失败按固定原因聚合，首个分钟事件入审计；数据库故障仍拒绝，日志限频。

作用域查询及可靠归档覆盖迁移 7 启用后产生的事件；旧 audit_events 保留，没有猜测历史客户端范围或宣称全部历史已归档。

<a id="archive"></a>
## 独立归档

`cmd/keygate-ops` 不提供 HTTP，数据库连接通过进程环境 KEYGATE_DATABASE_URL 提供，不把真实连接串作为命令参数或写入文档。签名私钥/固定公钥放在独立私有目录，文件 0600，目录 0700；生产应由独立权限和不可变存储接管。

| action | 输入与处理 |
| --- | --- |
| init-signing | signing-key、public-key 两个不存在的文件路径；仅生成本地运维签名材料，不打印秘密、不访问数据库 |
| archive | environment、archive-dir、signing-key、public-key；每批 limit=1..1000，先签名持久化事件，再确认数据库 outbox；可重复执行至本批为零 |
| seal-archive | 同上及 checkpoint；要求当前事件全部归档、核对期间集合不变；清单必须位于真实归档目录之外并独立保管 |
| verify-archive | environment、archive-dir、public-key、checkpoint；逐事件验签、集合摘要比对，再逐条与数据库事件比对 |

示例仅含公开路径占位，连接资料从本机私有配置载入：

```sh
go run ./cmd/keygate-ops -action archive -environment ENVIRONMENT \
  -archive-dir /private/keygate-archive \
  -signing-key /private/keygate-trust/archive-signing.key \
  -public-key /private/keygate-trust/archive-public.key
```

正式归档采用完整临时文件加排他发布、文件及父目录 fsync；相同事件相同内容重复成功，内容冲突拒绝覆盖。崩溃发生在外部写成功、outbox 确认之前时，可安全重试。部分临时文件不算正式事件。

签名发现事件篡改；独立清单发现删档；数据库比对发现已归档事件被删改或备份回退。后续增加归档事件后，需要生成新的清单文件；旧清单只证明旧集合，不能覆盖新增集合。私钥、公钥和“最新可信清单”必须由独立受控流程保管，同一目录中的自报 hash 不能证明安全。

<a id="backup"></a>
## 备份、状态核验与恢复启动

这是开发软件模式的受控离线恢复路径，不是在线自动灾备或生产 RTO/RPO 承诺。

1. 停止使用该库的全部实例、归档写入器和迁移；隔离操作数据库，使用受控运维身份。在同一 PostgreSQL 版本和模式下操作。
2. 完成归档及独立清单，执行 capture-state，签署当前安全状态摘要；在没有后续写入的情况下用受控 PostgreSQL 备份工具取得对应备份。签名校验点必须在备份之外保存，并独立确定哪个是最新可信版本。
3. 恢复到隔离数据库，运行 verify-state。任一表摘要/行数不一致，拒绝继续，不用回滚根预算或撤销事实来迎合旧备份，也不签署受损状态绕过核对。
4. 核对通过后执行 quarantine-state；采用 EXCLUSIVE NOWAIT 锁表，发现活动事务即拒绝；复核后原子停用全部插件及客户端、撤销旧会话、取消未执行申请、停用 pending/staged 候选、终止旧轮换/恢复并失效导出载荷。保留幂等、执行、撤销和根用量事实，不重开 bootstrap。
5. 针对隔离后的新状态再次 capture-state，使用新的文件路径保存签名校验点。
6. 显式恢复原管理域：

```sh
KEYGATE_ENV=development KEYGATE_ROOT_MODE=development_software \
  go run ./cmd/keygate-dev -enable-key-flow \
  -resume-environment ENVIRONMENT \
  -resume-checkpoint /private/keygate-trust/post-quarantine.json \
  -resume-public-key /private/keygate-trust/archive-public.key
```

启动先用固定公钥验签并精确比对安全状态，再确认原域已隔离；身份与角色沿用原域，新登录才能操作。恢复时根集合为空，不加载或重新生成旧软件根；先独立审批启用内部插件（原域须已有全域 PolicyAdmin；迁移不自动授予），再审批创建新根，最后对每个客户端走隔离换钥的两次独立审批。默认不带 resume 参数的演示启动仍创建新隔离域。

| 状态 action | 输入 |
| --- | --- |
| capture-state | environment、signing-key、public-key、checkpoint 新文件路径 |
| verify-state | environment、public-key、checkpoint |
| quarantine-state | 同上；校验通过也仅减权，不恢复认证 |

摘要覆盖插件候选/策略/检查、人员/授权、Profile、客户端、策略、申请/票/执行/幂等、根身份及预算、版本、轮换、恢复、撤销、会话、作用域审计/outbox、防重放及迁移状态，不输出这些表的敏感内容。nonce 作用域已哈希不能反查环境，故保守核验全库 nonce；共享库其他域变动会拒绝核验，需要一起停机。

最新校验点的新鲜度由外部保管流程保证，签名本身不能证明“这是最新一份”。不提供自动将旧备份追平到新状态、自动接管旧主或恢复软件根材料的入口。真实 KMS/HSM、跨中心隔离、独立不可变保管和实际灾备演练后续接入。

<a id="validation"></a>
## 失败处理与验证

- 请求/执行响应丢失：按原幂等键及申请执行日志核对；同一已成功本地操作不重复执行。
- 领取响应丢失：不重发秘密，撤销或停用旧版后申请新版本。
- 恢复期间撤权、改策略、目标修订变化、证据变化或密钥到期：旧票不再可执行，重新申请；中止不返还根预算。
- 数据库或审计故障：敏感变更回滚，认证拒绝；外部归档故障保留 outbox，不能假报归档成功。
- 外部归档/校验点核验失败：保持隔离，保留证据，不自动修补或覆盖原文件。

验证入口：`python3 scripts/test-postgres.py` 跑独立临时 PostgreSQL 全量 race；`go vet ./...`、`node --check internal/webauth/manage.js`、`python3 scripts/signature-vector.py`。覆盖轮换来源并行绕过、期限、终态撤销、隔离恢复与原子回滚、旧票失效、预算/nonce/撤销快照偏差、审计范围/撤权/快照、归档重试/篡改/删档和真实 TLS HTTP 管理调用。

当前未接入其他业务或生产基础设施，未修改 base 公共模块。原生客户端/BFF 完整业务认证、真实人员 MFA、跨机/多中心及生产发布验收不属于本批生命周期交付。

本批另已实测编译后 CLI 与三个独立模拟 SSO 会话、独立签名归档、原域隔离后 resume，以及真实 pg_dump/pg_restore 到一次性 PostgreSQL 16 容器的摘要与隔离核验。单机测试不等于真实多中心或生产根恢复验收。
