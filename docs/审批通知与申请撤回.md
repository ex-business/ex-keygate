<a id="flow"></a>
## 使用流程

管理页进入“审批中心”，个人通知支持服务端分页、关键词及时间筛选，见[申请与通知查询](申请与通知查询.md)，可筛选未读、标记已读或打开申请。读取通知仍要求已登录且完成当前策略要求的本人验证；人员停用或原冻结授权失效后不能读取旧通知。

```text
申请人提交
    |
    v
当前审批人收到待办 -> 完成本人验证并审批 -> 下一位收到待办
    |                                      |
    |                    达到门槛 -> 申请人收到待执行通知
    |                                      |
    +--- 申请人撤回                         +--- 申请人执行
    |                                      |
    v                                      v
保留原票、原因及审计                    记录执行结果
    |
    +--- 任一结果通知相关人员；旧待办不再允许操作

未结束申请 -> 剩余不超过1分钟提醒 -> 到期通知并拒绝审批/执行
```

通知不授予权限，不包含密码、验证码、密钥或完整操作载荷。审批和执行始终以权威数据库中的当前状态、冻结清单和本人验证为准。

申请详情中，原申请人可以撤回尚未执行且未过期、未失效的待审批或已批准申请。填写原因并确认后提交；申请人须保留原冻结授权并完成近期本人验证。其他人不能代撤回。已启动执行（包括远程结果未知）的申请不可撤回，已执行操作不能通过撤回恢复。

<a id="api"></a>
## 接口与状态

| 接口 | 用途与返回判断 |
| --- | --- |
| `GET /api/notifications` | 兼容旧接口返回本人最近100条通知，新页面使用分页查询；`read`决定未读显示，`kind`决定业务提示，`state`仅表示外部插件投递状态 |
| `POST /api/notifications/{id}/read` | 空JSON对象；仅本人可操作，成功204，重复标读保持原时间 |
| `POST /api/requests/{id}/withdraw` | JSON `digest`为当前冻结摘要，`reason`为必填原因，3至500个UTF-8字节；成功200返回申请详情 |

写接口要求管理会话、同源请求和 `X-CSRF-Token`。403表示身份、权限或验证不满足；409表示摘要、状态或执行竞争冲突，应重新读取申请。不得在409后自动提交新申请或继续执行。

撤回后返回 `decision=cancelled`，同时有 `withdrawnBy`、`withdrawnAt`、`withdrawalReason`；页面显示“已撤回”。仅 `cancelled` 而没有撤回人可能是其他受控失效流程，不应显示为本人撤回。`expired`来自数据库时间，不以浏览器本地时钟作为执行依据。

原申请人携带相同摘要和原因重试已成功的撤回具有幂等性，仍需满足本人身份校验。改变原因、摘要或撤回他人申请均拒绝。原票保留，请求级验证凭证失效；撤回与投票、执行共用域锁及请求锁，执行先占用时撤回失败。

通知类型包括 `approval_turn`、`approval_ready`、`approval_due`、`approval_expired`、`approval_rejected`、`approval_withdrawn`、`approval_executed`、`approval_invalidated`。顺序审批只通知当前处理人，非顺序审批通知未投票的合格成员；到期前通知申请人及当前待处理人员，终态通知仍具原冻结资格的相关人员。

<a id="plugin"></a>
## 通知插件

不配置插件时站内收件箱仍可用，外部状态为等待投递。配置 `-approval-notify-plugin-file /absolute/approval-notify.json`，持久部署对应 `approvalNotifyFile`。结构沿用证书提醒插件：

```json
{
  "url": "https://notify.example.com/approval",
  "allowedIPs": ["192.0.2.10"],
  "caFile": "/private/notify-ca.pem",
  "certificateFile": "/private/keygate-notify.pem",
  "keyFile": "/private/keygate-notify.key"
}
```

文件及私钥按插件配置校验保护，端点必须HTTPS并通过mTLS，禁止重定向及未经允许的目标IP。收件邮件/手机号由可信插件按 `recipientId`维护，申请人不能在请求中指定任意收件地址。邮件和短信厂商在该插件后接入，当前不代表已接真实厂商。

POST载荷仅 `id`、`requestId`、`recipientId`、`kind`、`digest`、`expiresAt`、`createdAt` 和固定 `path=/manage#approvals`。插件需用配置好的可信平台域名构造链接，不从申请内容取域名。`Idempotency-Key`固定为通知ID，重试载荷一致；插件必须持久去重。HTTP200/204代表已确认接收，202和其他结果按未确认处理。

队列先事务落库，外部I/O在事务外，单次最多10秒；失败按30秒乘尝试次数退避，最多5次后保留 `failed`。支持节点崩溃后的30秒租约接续；这是至少一次投递，确认丢失可能重复发送。`sent`只代表插件确认接收，不能证明用户已读或短信已送达。

过期、交接或撤回后，未发送的旧任务标为 `obsolete`；已发出的在途消息无法召回，迟到确认不能恢复旧任务。收件人打开后必须重新核对申请。失败任务可经全域策略管理员受控重排，保留原标识及历史，见[通知运维](通知运维.md)。

<a id="limits"></a>
## 升级与边界

【涉及其他业务】审批、执行、顺序交接在原事务内增加通知记录；通知初始于schema22引入，当前schema23新增投递历史和告警表，检查点覆盖这些数据。已有持久部署必须停服、生成最新签名检查点并走受控升级，普通启动不执行DDL，也不重建管理域。21/22→23在核验旧检查点后同事务迁移并发布，新DDL或修订失败一起回滚。旧版本不能加入新schema。详见[持久启动与受控升级](持久启动与受控升级.md)。

扫描约每10秒处理最多100个到期任务；大量积压、节点离线或插件故障会导致提醒延迟。到期拒绝不依赖通知成功。升级不补发已结束的历史申请通知；仍在进行的申请由扫描接续。该实现不含真实邮件/短信厂商开户、投递回执、值班升级链、通知归档及完整生产容量验收。
