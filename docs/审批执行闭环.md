# 开发审批执行闭环

首个获批业务为创建客户端：有效会话 → 当前 requester 范围检查 → 冻结申请 → 两名独立 approver 投票 → 可信内部执行器复查 → 同事务创建客户端和执行审计。未开放 HTTP 管理入口，不自动授权模拟账号。

新流程使用独立 `control_requests`、`control_votes`、`control_executions` 与幂等表，不接受旧 `approval_requests` 的内部摘要和旧票。编号 2 迁移追加表，不修改编号 1 的校验和。

## 固定清单与授权

服务端生成 `keygate-control-jcs-v1` 清单。受限 JCS 编码仅支持 ASCII 字段名、有效 Unicode 字符串、布尔值、空值、数组及安全整数，不接受任意外部 JSON 或浮点数；大版本按十进制字符串编码。清单包含环境、申请 ID、申请人自然人及修订、操作内容、目标修订、当前策略、审批池及人员/授权修订、创建与五分钟截止时间，摘要为 SHA-256。

审批人不能编辑执行参数。每次投票核对摘要、当前人员、角色范围及审批池；申请人及其自然人关联账号排除。数据库同时唯一约束申请/账号和申请/自然人；任意拒绝终止申请。

执行时重新检查申请人、每张票、人员和授权修订、审批池、策略、目标和 Profile 状态。撤权、自然人映射变动、旧策略或目标竞争不通过；不会替换审批人后继续使用旧票。

## 原子性与重试

同域控制行串行化审批、撤权和执行。当前创建客户端是本地数据库副作用，资格检查、唯一执行记录、客户端写入、申请完成及审计同事务提交，不需要模拟远程成功。相同申请重复执行只返回已完成，不重复创建；相同幂等键改变参数返回冲突。

后续 KMS/HSM 或第三方操作不能复用这个同事务副作用模型，必须另做占用、fencing、结果核对和 UNKNOWN 状态，当前不提供此执行器。

## 验证范围

临时 PostgreSQL 覆盖自批、未在审批池的同人账号、错误摘要、并发重复投票、票不足、并发重复执行、幂等内容冲突、撤权、策略变化、目标竞争和自然人映射变化。真实登录接授权的测试保留在 webauth 包。

客户端创建现已接续[软件密钥签发、加密交付、持有证明、审批激活、轮换与停用](软件密钥操作闭环.md)，仍以开发内核和集成测试交付。未接入现有业务数据库或 base 模块；网关与 SDK 仍未修改或联调。
