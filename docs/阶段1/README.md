## 关键决定

- 基础 KEK 不下发客户端，生产前接 KMS/HSM；软件根只用于开发。
- 后端 HMAC 采用 RFC 9421，而非自创签名拼串；浏览器不保存长期共享秘密。
- 所有类型均登记并独立配置；不受控原生端不能靠同一嵌入式秘密证明应用可信。
- OIDC 只确认身份。本地权限、审批资格、自然人映射与资源范围由权威库控制。
- 默认至少 2 人批准，申请人及其其他账号不计票；人数可按受控策略调整，不能低于安全基线。
- 签发、交付、激活、批准和执行分别记录，不把一个“成功”混用于所有步骤。
- 安全状态同库事务与版本检查；远程副作用明确 UNKNOWN，不能盲目重试。

## 阶段 2 进入顺序

1. 先实现人员/范围/策略及客户端模型，继续保持没有本地授权的会话不能操作业务。
2. 再实现申请、投票和执行占用，补齐自然人去重与当前权限检查。
3. 接内部客户端密钥 Provider、受控交付、激活及标准签名执行器。
4. 把停用、轮换、并发与错误路径做成完整闭环后再开放对应业务入口。
