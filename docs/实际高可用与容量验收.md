# 实际高可用与容量验收

- [验收内容](#acceptance)

执行 `python3 scripts/test-ha-capacity.py`，需要本机 Docker、Go 和 Python。脚本创建独立容器、前端与数据网络、临时数据库和随机凭据，结束时按唯一标签清理；不切换现有运营管理服务的数据库。私有结果保存在 `data/keygate-ha-*/report.json`，包含镜像摘要和实际测量值，不提交密钥及运行日志。

```text
TLS client -> HAProxy -> authentication node A/B -> database router
                                                     |
                                               PostgreSQL primary
                                                     |
                                            synchronous standby
```

<a id="acceptance"></a>

## 验收内容

| 场景 | 通过条件 |
| --- | --- |
| 实际负载均衡 | 经验证CA的TLS1.3入口，两节点均处理认证；跨节点重放拒绝 |
| 数据网络断开 | 切断A的数据网络，保留前端；A不就绪，B继续认证 |
| 旧节点隔离 | 超过租约后重连不能自行复活；显式重启登记推进实例代次 |
| 数据库切换 | 确认同步副本已有撤销，停止并核实旧主，才提升备库 |
| 权威切换 | 新库先推进集群代次，再切数据库路由；旧许可明确返回隔离拒绝 |
| 切换后认证 | 新节点、新版本成功；旧撤销版本与未过期nonce重放均拒绝 |
| 容量 | 并发1/4/8/16，错误率不超过1%，P95不超过1000ms |

容器节点直接运行生产认证执行器和节点租约，HTTP/TLS包装仅存在于测试二进制。容量路径包含同步数据库事务；不覆盖生产主程序的完整管理接口、全局入口限流、真实SSO与外部插件。长连接按连接分流，不能要求每一个负载档请求都平均分布。

| 8 | 160 | 160 | 560.01 | 27.516 | 45.468 |

基线8次连接两节点各4次。网络故障至重新登记共18.88秒（包含主动等待租约失效）；数据库停止、提升、推进代次、重启节点及验证共4.12秒。这是一次本机演练耗时，不是生产RTO承诺。资源数据为测试后的单次采样，不代表峰值。

<a id="boundaries"></a>

## 部署边界

这是隔离Docker环境的真实网络与同步复制演练，未验证生产容量、多机网络、多数据中心、长时间稳定性、生产RPO/RTO或自动故障仲裁。数据库提升由脚本显式编排，旧主必须先物理停止；没有实现自动选主系统。提升后只有一个权威库，生产恢复服务前还需重新建立同步副本。

数据库测试网络使用隔离环境内的明文连接；生产仍需数据库TLS、独立运行身份和网络访问控制。软件根用于开发测试，KMS/HSM继续预留。生产容量需在目标硬件上，按实际报文、密钥数量、长期并发、限流策略及外部依赖重新压测。

【涉及其他业务】安全验收脚本新增此演练，会增加Docker资源使用和验收耗时；使用独立数据库、管理域及网络。未修改管理端、H5和生产认证逻辑；未对现有运营数据注入故障。
