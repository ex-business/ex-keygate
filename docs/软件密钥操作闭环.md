# 开发软件密钥操作闭环

本批在既有客户端审批流程之上，增加签发、加密领取、持有证明、单独审批激活、轮换及停用。入口是受控进程内 Go 接口，没有开放 HTTP 密钥 API，也没有向现有模拟 SSO 用户自动授予权限。生产启动限制保持生效。

## 操作顺序

1. 离线初始化人员、授权和 Profile，经两人审批创建后端 HMAC 客户端。
2. 通过独立根预算和根登记接口配置专用客户端根。配置不得复用登录 PKCE 根。根 ID 绑定 SHA-256 材料指纹，客户端根之间相同材料不能用不同别名注册；调用者仍须保证与登录根的实际材料独立。
3. requester 提交签发申请，冻结客户端预期修订、下一版本、根 ID、接收方独立加密/签名公钥及各自指纹、到期时间。两人批准后，`DevelopmentKeys.ExecuteIssue` 生成独立 32 字节随机秘密。
4. 库中仅存 AES-GCM 密文；交付副本使用批准的接收方 RSA 公钥加密。签发后为 pending，不能激活或用于正常认证。
5. 接收方取得非秘密挑战，用批准的 Ed25519 签名公钥对应私钥签名领取。原子消费领取资格后返回加密副本、解密标签和独立持有证明输入。
6. 接收方本地解密，以客户端秘密对持有证明输入做 HMAC-SHA256。验证通过转为 staged，并增加客户端修订。
7. 再发起激活申请，两人重新批准后激活。正常停用也需要独立审批；应急角色可直接停用整个客户端，不能恢复。

## 交付约束

- 仅接受规范 DER SubjectPublicKeyInfo 的 RSA 3072/4096 位公钥，指数为 65537。公钥用无填充标准 base64 编码，指纹为 DER 的小写 SHA-256 十六进制。
- 交付包使用 RSA-OAEP / SHA-256，标签包含环境、客户端、版本、签发申请、接收方指纹和固定交付用途。
- 领取签名使用独立的 Ed25519 密钥，不复用 RSA 加密密钥。签名公钥同样采用 DER SubjectPublicKeyInfo 的无填充标准 base64 与 SHA-256 指纹，两把公钥和指纹一起冻结审批。独立 32 字节挑战、两把公钥指纹及相同上下文采用受限 JCS 编码，Ed25519 直接签署该编码消息。
- 持有证明采用另一个独立随机挑战及 enrollment 用途标识；不能复用领取签名或普通认证消息。
- 挑战最长有效五分钟，并受密钥到期、客户端/Profile/根状态限制。领取仅一次；响应丢失不重发，需停用旧版本并重新签发。
- 这些是开发交付协议。正式适配器仍需接收方公钥登记与指纹核验、可信 TLS、速率限制、消息大小限制和独立协议审计；当前不提供公网端点或管理员明文代领。

## 状态、轮换与原子性

签发、持有证明、激活和停用都会更新客户端修订，旧申请目标修订失效时不自动重算。每个客户端最多一个 active 和一个 retiring 版本，数据库唯一索引兜底。轮换激活须明确批准旧版本退役截止时间，最长十五分钟且不超过旧密钥原期限；尚有有效 retiring 版本时拒绝再次激活。

软件签发在初次授权检查后独立持久消耗根预算，再执行本地预计算，最后重新检查当前资格、根、Profile、目标版本并原子提交密文、执行记录与审计。预计算不产生远程副作用；竞争失败、停用或提交失败丢弃结果仍消耗预算。并发签发同一申请可能多消耗预算，但只能提交一个版本；已完成申请再次执行不消耗预算。

本地激活、停用与创建客户端同事务执行。此模型不能直接用于远程 KMS/HSM、第三方签发或网络交付，远程执行占用、fencing 与 UNKNOWN 核对仍待单独实现。

## 已验证及未交付

临时 PostgreSQL 全量 race 测试覆盖完整生命周期、领取私钥证明、错误持有证明、一次性并发领取、OAEP 目标绑定、激活前置条件、轮换唯一性、停用不恢复、完成重试不耗预算，以及预算阻塞期间应急停用后晚到签发结果不能写回。

本批完成的是开发内核和集成测试。正式 HTTP Message Signatures 业务认证执行器、管理/交付 HTTP 适配器、管理页面、真实 MFA、受控生产初始化、硬件与第三方 Provider、多中心部署及灾备验收尚未交付，不将 enrollment HMAC 当成业务认证协议。

【其他业务影响待确认】未来接入网关、SDK 和资源服务时仍需分别验证；本批未修改或连接其他业务数据库、网关或 base。
