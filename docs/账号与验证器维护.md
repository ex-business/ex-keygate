# 账号与验证器维护

范围为 ExKeyGate 的管理人员与审批人。人员登记和角色授权见[人员与审批策略在线治理](人员与审批策略在线治理.md)。本功能不会自动给人员授予角色。

## 页面入口

管理平台「人员与权限」中，具备全域 requester、policy_admin 权限且完成近期本人 MFA 的申请人，点击目标人员的「账号与验证器」。审批人按现有顺序逐人完成自己的验证并审批，达到当前 M 人门槛后，由原申请人执行。

本人设置页为 `/account-setup`。无需把交付码放进链接；在页面的密码输入框中填写。本人修改密码也在此页，需要已登录、近期 MFA 和原密码。

## 四种维护方式

| 方式 | 适用条件 | 最终启用要求 |
| --- | --- | --- |
| 首次绑定 enroll | 目标尚未配置 MFA | 已审批交付码，逐项证明全部新验证器 |
| 正常绑定／换绑 bind | 目标已有 MFA | 已审批交付码，全部新绑定证明，以及目标本人当前有效的管理 MFA 会话 |
| 丢失恢复 recover | 原验证器丢失 | 明确恢复申请、独立多人审批、全部新绑定证明；禁止保留旧验证器 |
| 账号启停／解锁 account_state | 已有本地账号 | 多人审批后直接执行；不产生交付码 |

申请人不能恢复自己的账号或修改同一自然人的别名。正常换绑允许目标本人发起，仍需独立的其他审批人；不能自己审批。受益自然人从该申请审批候选中排除，人数不足则拒绝。比如仅有两名审批人、要求两人同意时，其中一人丢失全部验证器，必须走组织受控离线恢复或事先设置备用审批人，不能在线降低门槛放行。

## 使用流程

```text
申请人选择人员、维护方式、新M-of-N策略
                 |
                 v
浏览器生成一次性交付码；服务器仅保存其摘要
                 |
                 v
当前策略的审批人按顺序验证、审阅旧/新策略、同意
                 |
                 v
申请人执行 -> 通过受控渠道将交付码交给本人
                 |
                 v
本人打开 /account-setup，输入交付码
                 |
                 v
添加新验证器 -> 每项证明持有 -> 可选设置新密码
                 |
                 v
正常换绑额外核验原MFA -> 原子启用 -> 旧会话失效
```

交付码在申请人页面内存中临时保存，默认遮盖，可在该申请详情中再次查看。刷新或退出后无法恢复；尚未交付就丢失时重新申请。不得把交付码、密码、TOTP 种子放入审批理由、聊天、日志或文档。交付码本身具有账号恢复能力，交付对象的线下身份核对与安全渠道由组织负责。

设置截止时间为原申请截止时间与执行后10分钟的较早者。当前申请窗口为5分钟，不是执行后再获得完整10分钟。人员修订、策略变更、申请人或审批人失去权限，均会使尚未完成的设置拒绝执行。

## 验证器与 M-of-N

每种方法分别设置 M/N，可设置该方法必需；外层 M 表示至少完成多少种方法。登录按照这些门槛执行。绑定阶段则要求 N 个候选全部证明持有，不能只绑定其中 M 个。

- TOTP：本人页生成并显示设置密钥，添加到验证器后输入六位动态码确认；不写入浏览器持久存储。只存加密种子，保留绑定的重放计数和猜测预算不会因换绑重置。
- 邮件／短信：由 HTTPS/mTLS 插件向新地址或手机号发送八位验证码，核验后才能启用。
- 硬件密钥：插件需额外实现 `/hardware/register/begin` 和 `/hardware/register/verify`。浏览器通过 WebAuthn 注册，插件必须验证 Origin、RP、挑战、attestation 和 user verification，并返回可信 credential；仅支持登录断言的旧插件不能用于注册。

插件请求和响应沿用严格 JSON、请求摘要、TLS 身份与目的地址限制。没有插件时拒绝该方式，不自动切换到较弱验证。真实邮件、短信和硬件厂商尚需各自验收。

每个候选最多5次核验、3次准备重试；重试不生成新候选、不重置验证码或预算。先预占候选名额，再封装秘密，重复或超出N的请求不能继续消耗根预算。封装失败后不释放名额，以免通过重建候选重置额度；无法恢复准备时重新申请。

## 账号维护

首次绑定或恢复可选择创建本地登录账号／重设密码；正常换绑也可选择本人设新密码。申请中仅含用户名，不含新密码；审批完成后由本人设置。已有用户名不能在线改名，人员身份和自然人关联也不在这里修改。

本人修改密码必须核对原密码，受跨节点登录预算、失败锁定及摘要修订检查约束。密码变更、验证器启用和账号启停／解锁均封禁当前安全域中的旧会话，重新登录后还需新 MFA。账号停用只关闭该本地密码入口；若需同时禁止 SSO 与全部管理权限，应在人员治理中停用人员。

## 审计、恢复及边界

申请内容、投票、执行、候选准备、核验结果、最终启用和密码更新记入现有审计，不记录秘密。审计仅记录处理事实，不保存线下身份核对材料；申请中填写材料摘要。

备份隔离恢复会同时消耗未完成的一次性设置票，包括已经执行审批的票；不能通过恢复数据库重新启用旧恢复码。

【涉及其他业务】复用密码登录、MFA、人员修订、会话封禁、审批及备份隔离路径。新增数据库迁移20和设置状态表；部署后不能直接回退旧二进制绕过新增设置票的隔离规则。KMS/HSM、真实厂商和生产部署验收仍按原计划推进。
