# 申请与个人通知查询

入口：审批中心。申请与个人通知分别有关键词、开始时间、结束时间、每页条数和翻页按钮。提交查询或更改状态、待办标签、未读筛选时从第一页开始；刷新数据也重新开始查询，标记通知已读保留当前查询位置。

时间按浏览器本地时区输入，传到服务端转为UTC，按创建时间过滤，包含开始时刻、不包含结束时刻。结束时间不填写时不设上界。申请时间为冻结清单的创建时间，通知时间为通知入队时间，二者不是投递完成时间。

| 查询 | 搜索字段 | 服务端筛选 |
| --- | --- | --- |
| 申请 | 申请ID、冻结的客户端标识、操作名称、申请人人员/身份标识 | 全部、待我处理、我发起、待我执行，及申请状态 |
| 个人通知 | 通知ID、申请ID、通知类型代码 | 本人通知、只看未读 |

关键词去除两端空白后按大小写不敏感的字面子串匹配，最多256个UTF-8字节；`%`和`_`没有通配含义。不搜索密码、密钥、恢复码、操作载荷、审批原因或收件地址。通知类型使用 `approval_turn`、`approval_expired` 等代码，不按页面中文提示搜索。

默认每页20条，可选10/20/50条；接口允许1至50条。每次最多检查200个候选记录，权限或状态过滤可能形成不足一页或空页；只要还有继续游标，就能继续向更早记录查询，不局限于最新100条。页面不展示未授权记录数量或标识，也不提供全库总条数。

## 接口

- `GET /api/requests/search?q=orders&view=applicant&limit=20`
- `GET /api/notifications/search?unread=true&limit=20`

共同参数：`q`、`from`、`until`、`limit`、`cursor`。时间为RFC3339（可带小数秒和时区）。申请另支持 `view=all|mine|applicant|execute` 与 `state`；个人通知支持 `unread=true|false`。未知参数、重复参数、非法时间范围和超限页大小拒绝。

成功返回 `{"items":[],"nextCursor":"..."}`，`nextCursor`为空表示本次查询已结束；下一页原样提交游标及全部相同筛选条件和页大小，不能自行改变游标。游标绑定环境、当前人员、查询种类、条件与首次查询时间，不是授权凭据。最大候选位置100万，超过此范围应收窄时间条件。申请的首次查询界限取数据库已结束的毫秒，避免同毫秒新建记录进入已开始的分页；刚提交的记录刷新后可见。排序为申请到期时间和ID倒序（当前申请固定五分钟有效期），通知为创建时间和ID倒序。

每页重新验证登录、本人验证及当前授权，申请沿用原查看范围，通知限定本人并复查冻结资格。撤权后不能用旧游标继续读旧数据；换身份、换条件或跨接口复用游标拒绝。返回的申请状态随数据库当前时间判断，翻页不是历史状态快照，也不授权审批或执行。数据被删除、迁移或后台调整时，应重新查询，不承诺跨页数据库快照一致性。

单次查询设三秒超时，继续使用现有共享限流；超时或限流时不要快速自动重试。空页有继续游标时由用户点击下一页，不自动连续遍历全库。

【涉及其他业务】新增只读路由及管理页查询，不改变旧 `GET /api/requests`、`GET /api/notifications` 数组返回，旧接口和工作台摘要仍最多100条。无需数据库迁移，现有审批、撤回和通知投递不变。旧浏览器请求可能较新查询晚返回，页面以身份代次、查询代次和刷新代次检查后才显示；验证失效后清空查询数据。
