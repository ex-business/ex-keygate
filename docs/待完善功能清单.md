## 已完成基线

下列已有能力继续复用，不重复列为新功能：

- 账号密码和原生二次验证，保留标准 OIDC/SSO 接入；本机模拟身份仅用于开发。
- 客户端范围授权、逐人 M-of-N 验证与审批、申请人确认执行。
- 共享密钥签发、加密领取、持有证明、启用、认证、轮换、撤销、隔离恢复。
- 多套独立应用根、业务证书审批发布、轮换与撤销、权威短时状态证明、Go 验证库与 CLI、独立根恢复协议。
- 独立「信任链管理」页面，按根展开业务服务与当前证书；密钥管理保留共享密钥。
- 同源 H5 认证与 TypeScript/ESM SDK。
- 审计查询、导出、独立签名归档及本地核验；共享 PostgreSQL 下的应用多节点并发与故障测试。

根与业务证书的生成、签发，以及初始人员引导，目前仍有受控离线操作。已有恢复协议不代表生产恢复编排或灾备验收已完成。

<a id="acceptance"></a>
## 功能与验收

### KG-01 证书详情与下载

- 展示根与业务证书的签发者、主体、序列号、指纹、用途、环境、服务标识、生效及到期时间，并明确当前版本和状态。
- 展示当前支持的直接「根 → 业务证书」关系及验证结果，不把证书详情展示当作新的认证依据；不宣称已支持中间 CA。
- 在原有查看权限范围内下载 PEM/DER 公开证书，禁止导出私钥、共享密钥、验证码或恢复私钥；撤权后重新检查下载权限。

### KG-02 历史版本与追踪

- 可按根和业务服务查看证书历史、发布申请、审批记录、执行时间、轮换关系及撤销原因。
- 区分当前版本、退休、停用、撤销和证书有效期；证书过期属于时间判断，不擅自改写已保存的撤销事实。
- 范围授权、分页和审计规则与现有目录一致；旧版本不能通过查看、下载或重发提案恢复为有效版本。

### KG-03 续期与到期提醒

- 根据证书实际期限给出到期列表，当前固定7天/24小时/1小时/已过期分级，受控阈值配置可后续补充；开发叶证书最长 24 小时的限制不直接当作生产策略。
- 续期生成新证书版本，经持有证明、逐人审批和申请人执行后发布；提醒或定时任务不得自动批准，也不得隐式换根。
- 独立设计状态签名证书的受控续签与节点配置更新，不把离线根私钥搬到在线管理服务。
- 验收重复提醒去重、证书已更新、已撤销、过期、节点停机及重试场景。外部通知经可靠任务投递，不在权威签名事务中等待。

### KG-04 人员、角色与策略在线治理

- 范围仅为管理人员和审批人，不扩展成业务 C 端用户平台。
- 提供新增、停用、角色及范围变更、审批人员和阈值策略变更的受控申请与审计；不能自行授予更高权限。
- 变更审批必须绑定具体内容与修订；人员停用、撤权或策略变更后，旧会话、旧票和待执行申请按现有资格复查规则处理，不能因新增页面绕过限制。

### KG-05 账号与验证方式维护

- 补齐管理账号的受控口令维护，以及 TOTP 绑定、邮件/短信绑定、硬件注册和换绑的页面流程。
- 首次绑定、换绑和设备丢失恢复分别定义身份核验、独立人员确认、旧凭据撤销和留痕要求；不能仅凭一次邮件或短信直接绕过既有多人授权。
- 验证组合继续支持已有策略。未配置可信插件、验证失败、证明过期或旧设备已撤销时拒绝操作，不提供降低门槛的找回入口。

### KG-06 正式运行与升级

- 提供明确的受控初始化与已有域加入、正常重启路径；日常重启不重建身份域、不重置修订、预算、防重放或撤销记录。
- 持久化配置只保存允许持久化的材料，密钥托管遵循已批准的 Provider；不能为实现重启而把开发内存根明文落盘。
- 定义版本兼容、数据库迁移、检查点更新、失败恢复和回退门禁；集群节点配置不一致、缺失可信状态或迁移不兼容时拒绝就绪。
- 多数据中心能力与生产根托管仍依赖 KG-09、KG-10，不因新增启动命令自动视为可生产运行。

### KG-07 审批通知与撤回

已实现，使用和接入说明见[审批通知与申请撤回](审批通知与申请撤回.md)。

- 交接、待办和超时提醒携带申请标识及安全管理入口，不发送秘密材料；收到通知不等于获得审批权限。
- 设计申请人撤回的允许状态及并发规则，撤回与审批/执行竞争必须只有一个合法结果；已执行操作不能被标记为未发生。
- 申请到期仍由权威时间拒绝；通知延迟、失败或重复不得改变批准门槛、恢复过期票或重复执行。新增撤回状态、审计和显示规则需同步验收。

### KG-08 真实厂商与身份接入

- 分别验收邮件、短信、硬件验证和实际 OIDC 身份平台；支持协议或模拟插件不代表已连接厂商。
- 核对 mTLS、身份与 MFA 结果映射、超时、限流、重复投递和回调真实性；厂商不可用时不降级放行。
- 有远程副作用的 Provider 还需验证操作占用、fencing、幂等、UNKNOWN 结果查询与恢复，不能用当前只读适配器代替。

<a id="production"></a>
## 生产准入与延后范围

### KG-09 生产安全与高可用

- 部署就绪检查、指标、告警、容量限制和敏感日志检查；监控目标和告警接收方必须明确。
- 在真实应用多节点、负载均衡、数据库主备及网络分区环境验证撤销一致性、防重放、旧主隔离和提交结果未知处理。
- 演练备份、还原、独立可信检查点、不可变审计归档和根恢复更新分发；明确并实测 RTO/RPO，不能以单机容器演练代替多中心验收。
- 解决客户端高权限磁盘回滚和可信时间边界，开展独立安全评估与渗透测试。开发安全验收通过不等于生产准入通过。

### KG-10 KMS/HSM

按用户约定延后实际接入，保留接口和失败关闭约束。真正上线前，需要完成根托管、最小权限、签名与解密、跨节点访问、故障、审计及恢复验收；不得提前解除当前生产启动阻断。

### KG-11 原生客户端

移动端、桌面端分别实现认证执行器、凭据安全存储、平台生命周期和 SDK 验收。当前 Go 证书验证库与 CLI、H5 SDK 已交付，不将它们重复列为未实现，也不据此声称原生端已经完成。

## 交付规则与影响

- 每项按数据/权限、接口、页面、边界与故障测试、文档拆分可审查提交；完成后更新本文状态及验证证据。
- 采用独立功能分支及 worktree；提交和推送前完成独立只读审查。P0/P1 修复并复审后才能提交。
- 本次只新增待办文档和导航，不修改运行代码、权限、配置、数据库或现有演示数据。
- 【涉及其他业务】后续 KG-04 至 KG-09 可能影响管理登录、审批、审计、检查点与现有 HMAC/H5 调用链；每批实施前明确影响并完成针对性回归，未验证项不能标为完成。本次文档变更无运行行为变化。
