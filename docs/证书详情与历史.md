<a id="use"></a>
## 查看与下载

1. 管理账号登录并完成本人 MFA，进入「信任链管理」。
2. 展开根分组，点击「根证书详情」查看主体、签发者、序列号、SHA-256 指纹、算法、用途及有效期。
3. 在业务服务行点击「详情与历史」，默认展示当前证书；在版本列表点击「查看 vN」切换到历史版本。
4. 使用「下载 PEM」「下载 DER」获取当前选中版本的公开证书。「查看所属根」进入根详情，可下载公开根证书。
5. 在变更记录点击「查看申请」，或在关联审批列表点击「查看详情」，进入原审批详情查看冻结内容和人员流转。

所有详情和下载都重新检查会话、本人 MFA、人员状态及当前 Viewer 范围。范围查看者只能查看自己有权服务关联的根；知道指纹、服务标识或旧下载地址不代表有权限。下载同事务记录审计，审计失败不返回证书。

PEM 与 DER 编码的是同一份公开 X.509 证书。下载不会导出私钥、共享密钥、验证码或恢复密钥，也不会重新发布、启用或更改证书。过期及已撤销证书可供有权人员查阅和公开下载，不能据此用于认证。

<a id="states"></a>
## 状态判断

| 字段 | 含义与操作判断 |
| --- | --- |
| `certificate.state` | 保存的生命周期：active、retired、disabled、revoked；不能把到期显示覆盖到撤销事实 |
| `certificate.current` | 是否为服务当前版本；历史版本不是当前可用版本 |
| `certificate.info.validity` | 数据库时间下的有效期判断：valid、expired、not_yet_valid |
| `rootInfo.validity` | 当前根证书的有效期状态 |
| `chainValid` | 根签名、叶签名和用途绑定在其有效时间区间内完整；不是当前认证成功的证明 |
| `authenticationEligible` | 当前版本、active、服务未停用、根及叶有效期内、链用途完整等证书侧条件同时满足 |
| `service.disabled` | 服务是否已被停用或隔离；即使证书本身仍有效，也不能按活动服务使用 |

实际认证仍必须经过现有实时状态签名、用途、正文、nonce、防重放及客户端持久状态验证。页面不提供替代认证接口的“验签通过即放行”功能。

根与业务证书采用应用内固定信任，不使用系统根或远程补链。本批展示直接「根 → 业务证书」，不新增中间 CA 能力。

<a id="api"></a>
## 接口与分页

以下均为 GET，要求同源管理会话及当前授权。只列公开资源路径，不在 URL 中携带凭据。

| 方法与路径 | 参数与返回 |
| --- | --- |
| `/api/trust/services/{service}/certificates` | `limit` 默认20、范围1–50；`before` 为正整数版本游标。返回 certificates、hasMore、nextBefore，版本倒序 |
| `/api/trust/services/{service}/certificates/{version}` | 返回业务、根、证书元信息、链完整性、证书侧资格、changes 和 approvals |
| `/api/trust/services/{service}/certificates/{version}/download` | `format=pem` 或 `format=der`，缺省pem；附件下载公开业务证书 |
| `/api/trust/roots/{fingerprint}` | 返回根及公开元信息；不接受额外查询参数 |
| `/api/trust/roots/{fingerprint}/download` | `format=pem` 或 `format=der`，缺省pem；附件下载公开根证书 |

例如历史首屏 `/api/trust/services/orders-api/certificates?limit=20`。仅当 hasMore 为 true 时，下一页传入返回的 nextBefore；例如 `?limit=20&before=3`。新版本插入不会改变游标之前的历史排序。

版本必须是规范正整数，不接受前导零，最大为 2^53-1。查询参数拒绝重复键、未知字段、非法编码、空查询标记及超过256字节的内容。新增证书只读路由保留共享限流；既有业务接口不因此放宽查询规则。

未登录为401；本人验证未完成、撤权或越范围为403；合法范围内记录不存在为404；非法参数为400；限流为429。存储、审计或权威状态不可用时拒绝，不下载缓存成功结果。

<a id="history"></a>
## 历史与变更边界

- 证书版本列表分页读取，展示当前标识、生命周期和有效期；详情一次展示该版本最近100条结构化变更及最近100个关联审批，超出时以 hasMore 标记说明，不宣称返回全部记录。
- 发布、被新版本替代、审批停用、应急撤销与结构化变更记录在同一事务完成；记录版本、修订、动作、原因、关联申请、操作人和数据库时间。
- 发布与普通停用关联批准申请；应急撤销关联应急操作者。重复撤销保持首个已提交原因，不新增重复事实。
- 迁移前的证书和申请仍可查询，但不会补造过去的操作时间或撤销原因。关联申请属于审批过程，不能把尚未执行的申请当作已经发生的证书变更。
- 管理域的隔离恢复仍按既有审计和检查点流程追踪；本批结构化变更表只记录上述四类证书操作。服务隔离状态独立显示，不把它冒充某次证书撤销。

<a id="verification"></a>
## 迁移与验证

新增迁移17 `application_trust_changes`，保留原证书和审批数据，不回填猜测事件。检查点表集包含新表；受控升级后重新生成可信检查点，旧检查点不能直接当作包含新表的完整恢复依据。混合版本节点不保证结构化追踪完整，应统一升级。

验证范围包含真实 PostgreSQL 权限及撤权、历史游标、不同根范围、重复撤销、过期证书仍可查阅且不可认证、变更记录写失败回滚；HTTP 参数白名单、原业务查询限制、公开 PEM/DER 和根下载；浏览器版本切换、申请跳转、下载内容比对及移动布局。

【涉及其他业务】本批复用审批执行、审计和检查点，增加证书变更事实及下载审计；不更改 HMAC/H5 认证协议，不自动执行续期、权限变更或硬件接入。生产安全验收仍需另行完成。
