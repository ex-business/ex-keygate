<a id="scope"></a>
## 范围与拓扑

本批实现应用多节点同时认证的存储边界、节点生命周期、可信开发节点加入接口、就绪探针和可执行验收。多个节点必须连接同一个权威 PostgreSQL 写入集群；不能将异步只读副本用于认证、会话、审批或防重放。

```text
                   +--------------------------+
Clients -- TLS --> | Reviewed load balancer   |
                   +-------------+------------+
                                 |
                     +-----------+-----------+
                     v                       v
                App node A              App node B
                active lease            active lease
                     |                       |
                     +-----------+-----------+
                                 v
                     Authoritative PostgreSQL
                     nonce / votes / revoke
                     node epochs / budgets
```

负载均衡、数据库主备和 KMS/HSM 不是本批自动安装的设施。默认 `cmd/keygate-dev` 仍创建单个隔离演示域和临时根，不可运行两次来冒充共享域集群。多节点由可信启动器使用下述接口装配，双进程验收不向生产分发软件根。

<a id="consistency"></a>
## 一致性与节点资格

| 对象 | 权威决策与失败行为 |
| --- | --- |
| 认证／撤销 | 同一安全域行锁排序，最终事务查询当前客户端、Profile、版本、根和插件状态；另一节点不缓存旧授权 |
| nonce | 共享唯一约束，同一签名跨节点最多一次成功；提交错误按拒绝处理 |
| 审批／执行 | 现有摘要、授权快照、投票、幂等和执行结果在共享库核验；节点切换不能重开旧票 |
| 包装用量 | 相同不可变 rootID 共用原子预算，失败不退款，不按节点重置 |
| 节点 | 集群代次、节点实例代次、随机实例秘密摘要及数据库时间租约；本机时钟不决定资格 |
| 配置 | 加入时核对受控配置摘要；摘要须覆盖实际共享身份、根引用、插件及部署配置，由启动器核实 |

迁移 10 增加 runtime_cluster/runtime_nodes。未启用集群时保留单机模式；受控离线启用后，没有节点许可的普通 Store 不能执行认证、会话、审批或预算操作，不提供关闭集群校验的产品接口。旧二进制不具备该检查，升级必须全部停服，不能混合版本。

不同 nodeID 可同时有效；同一 nodeID 的活跃实例不能被抢占。租约为 15 秒，续约循环每 5 秒执行、单次两秒超时。过期后续约拒绝，必须重新申请并增加 incarnation；配置或全局代次变化后旧许可失效。租约秘密只在内存中，不写入 HTTP、配置文件或日志。

业务事务先取得集群、节点共享行锁，再进入业务域锁。续约／摘流直接取得节点排他行锁，避免共享锁升级死锁；接管／隔离不能越过已经开始的业务事务。已经提交的结果可能在切换后才到达客户端，其线性化点仍在提交时，不追溯撤销已提交操作。业务事务限制单条语句、锁等待和空闲事务，避免异常连接长期占锁；这些限制不构成整体请求延迟承诺。

<a id="startup"></a>
## 可信启动装配

以下为内部 Go 装配接口，不挂管理 HTTP；数据库凭据、配置摘要和开发根不得由客户端提供。

1. 显式迁移专用数据库。受控初始化域、角色、Profile、根和预算只执行一次，不按节点重复 bootstrap。
2. 停服核验配置后，调用 `Store.ConfigureClusterOffline(ctx, clusterID, configurationHash, trace)`；已启用时拒绝覆盖。
3. 各节点使用独立连接池，调用 `AcquireNode(ctx, clusterID, configurationHash, nodeID, trace)`，取得绑定本实例的 Store。加入失败／提交不明不返回许可，不盲目重新抢占。
4. 登录 Protector、Service、DevelopmentControl 和客户端密钥执行器均绑定这个节点 Store；不能混用未登记的旧 Store。启动器负责由相同实际配置产生摘要，代码不会凭一个摘要证明配置已被人工审核。
5. `Service.AttachSimulatedNode(ctx, environment, []DevelopmentRoot)` 仅加入已有开发域，验证根指纹；不创建管理员、预算或替换根。输入材料只能从受保护通道短暂提供，调用后清除启动器持有的字节。该接口没有根分发或持久化功能。
6. 在 Handler 构造前完成 `ConfigureDevelopmentPlugins`；节点运行 `RunNodeLease`。Handler 构造后拒绝新增或替换安全域。
7. 成功就绪后才交给负载均衡。多根加入不猜测新签发默认根；新根生成和密钥生命周期仍按现有多人审批流程。

同一浏览器入口必须使用相同回调 origin、身份策略、实际登录保护根及客户端根。根新增后其他节点不会自动获得材料；缺根节点立即不再满足就绪，需通过可信托管／启动装配补齐。真实共享托管按要求待 KMS/HSM 接入，不能将测试管道机制复制到生产。

<a id="readiness"></a>
## 就绪与摘流

| 接口／方法 | 含义 |
| --- | --- |
| GET /health/live | 进程存活，不访问数据库，不代表认证可用 |
| GET /health/ready | 当前权威库可写、节点资格有效、内部插件启用且本节点装配全部已启用根时返回 200，否则 503；两秒超时，不缓存成功，不输出内部引用 |
| Store.DrainNode | 等已开始事务释放节点共享锁后提交摘流，新业务事务拒绝；随后才停止监听 |
| Store.FenceClusterOffline | 停服并完成外部旧主隔离后推进全局代次，当前库的全部旧节点许可失效；不自动复活 |

探针只是某个时刻的观察，真实业务仍在每个事务内重查。负载均衡须配置就绪检查、节点移除和 TLS；主机名、方法、原始路径、查询、正文和签名字段必须保持一致，不通过未受信转发头重建签名。管理恢复入口应有独立受控路径，避免全部认证节点未就绪时无法修复配置。

<a id="failure"></a>
## 故障处理

| 故障 | 行为与恢复 |
| --- | --- |
| 一个应用进程退出 | 其他节点继续使用共享状态认证；移除故障节点，等待其租约到期，重启取得新 incarnation |
| 一个节点数据库连接断开 | 本节点拒绝；其他连接池可继续工作；过期实例即使网络恢复也不能自动续活 |
| 相同 nodeID 重复启动 | 有效旧租约期间拒绝新实例；不因重启重置 nonce、预算、审批或执行结果 |
| 数据库不可用／只读 | 所有受影响节点拒绝，禁止本地缓存放行和转向异步副本 |
| 操作提交结果不明 | 认证按失败；管理操作查询原请求及幂等结果，不能自动生成新票／重复发钥；客户端重试认证使用新签名和 nonce |
| 数据库主备切换 | 外部先保证旧主物理隔离和安全状态不丢失，再验证新权威库、推进代次并重新加入节点；未确认则保持拒绝 |
| 备份恢复 | 按生命周期手册验证独立最新签名校验点并 quarantine；同时推进集群代次、停用插件、撤销会话和旧票，再按序重新审批恢复 |

一个独立旧主库仍能接受写入时，它有自己的代次和租约数据，应用内 fencing 不能使它失效。数据库同步复制、仲裁与旧主隔离必须由部署设施保证；本批不声称实现数据库选举或多中心共识。迁移后需在停服状态重新生成包含集群表的安全校验点，旧表清单不能直接用于新版本恢复。

<a id="acceptance"></a>
## 验收入口

```sh
python3 scripts/security-acceptance.py
```

需要 Docker、Go、Node 和网络访问漏洞数据库。脚本在私有、忽略的 `data/security-acceptance-*` 保存逐项日志和 report.json；记录提交、工作区是否有改动、结果和耗时，失败即停。固定 govulncheck v1.9.0，网络失败或扫描失败不能记为通过。

| 检查 | 证据范围 |
| --- | --- |
| diff、vet、JS 语法 | 提交格式、Go 静态检查和管理脚本 |
| 固定签名向量 | Go／Python 协议一致性 |
| 开发数据库脚本边界 | 容器所有权、隔离文件和清理行为 |
| PostgreSQL 全量 race | 权限、审批、生命周期、审计故障回滚及已有安全回归 |
| TestClusterNodeFencingAndConfiguration | 配置不一致、重名抢占、过期、旧许可、摘流与全局隔离 |
| TestClusterConcurrentRenewalsDoNotUpgradeSharedLocks | 并发续约不发生共享锁升级死锁 |
| TestClusterTakeoverWaitsForInFlightTransaction | 隔离不能越过已开始事务 |
| TestClusterIndependentPoolsShareAuthenticationAndRevocation | 两个独立连接池的 nonce 一次消费、停用立即可见和单节点断连 |
| TestClusterSeparateProcessesSurviveNodeFailure | 两个真实子进程认证、跨进程重放拒绝、杀死节点、实际等待租约、重启并推进实例代次；测试根仅经匿名管道传递 |
| 就绪测试 | 缺根、插件停用、数据库断开时 503；存活仍 200；错根不能加入已有域 |
| govulncheck | 当前已知、可达漏洞检查，不等于完整安全认证 |

双进程测试调用实际 AuthenticateProbe 处理经 HTTP 格式序列化的签名请求；它不是实际负载均衡／跨机器网络分区演练，不作为相应部署验收证据。

<a id="production"></a>
## 生产门禁

报告分别给出 engineeringStatus 和 productionStatus。代码和开发故障演练全部通过时前者为 PASS；后者仍固定 BLOCKED，直至真实环境完成：OIDC/MFA 与人员治理、最小权限数据库身份、KMS/HSM、同步复制与旧主隔离、TLS／负载均衡、提交不明与网络分区、多中心 RTO/RPO、独立不可变审计、告警和渗透测试。默认生产软件根仍被配置层拒绝。

本批仅修改 ExKeyGate。未修改其他业务、base 公共代码或现有业务数据库。
