<a id="scope"></a>
## 当前范围

`keygate-backup`是独立运维进程，支持单管理域专用PostgreSQL的在线加密数据库备份、独立签名检查点、定时运行和空库隔离还原。备份使用只读repeatable-read事务导出的同一个快照生成检查点和pg_dump，认证与撤销仍可运行。

恢复只得到隔离状态，不自动恢复业务认证。所有备份中的旧客户端基础根停用，旧密钥版本永久转为compromised；旧会话、审批票、一次性授权和告警任务一并失效。即使备份缺少后来的撤销事实，重新打开客户端开关也不能让旧密钥复活。业务恢复需要新根、新密钥、重新审批，并核对人员权限等恢复状态。

此功能备份数据库的keygate schema，不包含数据库全局角色、其他schema、部署加密材料、TLS/插件配置、包装密钥或离线根私钥。这些材料必须按原有部署和密钥恢复规范另行保管；不能把数据库备份称为整机完整备份。

<a id="configuration"></a>
## 准备与配置

准备与源数据库兼容的pg_dump、pg_restore、psql。备份、检查点目录0700，配置与密钥文件0600；使用绝对路径。检查点目录不能位于备份目录内，两个目录也不能互相包含。签名私钥、固定公钥、32字节加密密钥及源数据库配置均放在这两个目录之外。最终路径的符号链接被拒绝，系统路径别名规范化后检查。

生成专用签名密钥：

```sh
keygate-ops -action init-signing \
  -signing-key /secure/backup/sign.key \
  -public-key /secure/backup/sign.pub
```

加密密钥为独立密码学随机32字节文件，不能复用业务根或登录密钥，不在聊天、日志或Git中传递。私钥与加密密钥另行备份，丢失加密密钥无法解密数据库备份。

```json
{
  "environment": "your-management-domain",
  "databaseFile": "/secure/backup/source-database-url",
  "directory": "/var/lib/ex-keygate-backups",
  "checkpointDirectory": "/var/lib/ex-keygate-checkpoints",
  "signingKeyFile": "/secure/backup/sign.key",
  "publicKeyFile": "/secure/backup/sign.pub",
  "encryptionKeyFile": "/secure/backup/encryption.key",
  "pgDump": "/usr/bin/pg_dump",
  "pgRestore": "/usr/bin/pg_restore",
  "psql": "/usr/bin/psql",
  "backupSeconds": 900,
  "checkpointSeconds": 60
}
```

| 配置 | 对行为的影响 |
| --- | --- |
| environment | 必须与唯一管理域一致，拒绝多管理域混合库，避免恢复未经检查的其他域 |
| databaseFile | 私有postgres/postgresql URL；数据库名须为合法标识符，不能含等号或连接串 |
| directory | 每次新建随机备份目录，保存database.kgb和签名manifest.signed |
| checkpointDirectory | 逐份不可覆盖的签名记录及原子更新latest.signed；本地文件不等于不可变异机见证 |
| backupSeconds | 60至604800秒；按上次完成后计算，失败保留日志，下一周期重试 |
| checkpointSeconds | 10至3600秒；备份完成后立即补存当前检查点；导出期间可能延迟，不能当成严格RPO承诺 |

源URL仅接受显式sslmode、sslrootcert、sslcert、sslkey、connect_timeout连接选项，拒绝未知和重复选项。连接凭据经子进程环境传递，不放在参数或日志中；清理继承的PG变量，防止隐式连接目标变化。

<a id="schedule"></a>
## 自动运行和检查点

```sh
keygate-backup -config /secure/backup/config.json -action backup
keygate-backup -config /secure/backup/config.json -action checkpoint
keygate-backup -config /secure/backup/config.json -action run
```

run启动先备份，再立即保存最新状态，随后按间隔运行。由操作系统服务管理进程，参见[systemd模板](../examples/keygate-backup.service)；按部署目录、专用账号及权限调整模板，不直接用于未经验收的生产环境。

同一备份根或检查点根仅允许一个写进程，以排他锁文件保护。正常退出释放锁；进程被强杀留下的锁须先确认无其他进程使用，再由运维移除，不能自动按时间抢锁。备份耗时上限30分钟，普通检查点一分钟；磁盘或远程文件系统阻塞还受操作系统行为影响。

备份逐文件派生独立AES-256-GCM密钥，分块认证，终块防截断。发布前同步密文、清单、备份父目录，最后发布独立签名记录与最新指针；失败不伪报成功。已有完整备份在后续发布失败时可能成为孤立文件，保留供核验，不自动删除。

成功输出checkpointFile、checkpointSHA256、backupId。自动模式输出中文结构化日志，须由独立保管方保存最新摘要或签名文件。仅持有同一备份目录里的旧清单不能证明新鲜度。恢复时必须显式提供来自独立可信见证的最新文件摘要，不能临时对备份自带旧清单算个hash冒充最新。

<a id="restore"></a>
## 恢复步骤

先停止和隔离旧认证节点、隔离旧主，准备独立空目标库。恢复工具拒绝非空库，不包含自动建库、删库、旧主隔离或负载均衡切换操作。目标不得挂接认证流量。

```text
independent latest checkpoint + externally pinned hash
                       |
                       v
backup signature + ciphertext integrity + complete decryption check
                       |
                       v
empty target: BEGIN -> pg_restore SQL -> compare table digests
                       -> revoke all old roots/keys/sessions/approvals
                       -> assert isolation -> COMMIT
failure anywhere ------> ROLLBACK
```

```sh
keygate-backup -config /secure/backup/config.json -action restore \
  -backup-id BACKUP_ID \
  -latest-checkpoint /independent/current-checkpoint.signed \
  -expected-checkpoint-sha256 EXTERNALLY_PINNED_SHA256 \
  -target-database-file /secure/backup/isolated-target-url \
  -confirm-empty-target keygate_restore_target
```

恢复端只需固定公钥、备份解密密钥与目标连接配置，不读取签名私钥或源数据库凭据。配置中的程序与存储位置仍须有效。

恢复先核对签名、环境、外部固定摘要与备份检查点，再校验完整密文并在只持有私有句柄的临时文件中冻结密文；不把明文数据库写到磁盘。pg_restore转SQL与psql使用同一事务，在COMMIT前重新按逐表摘要核对，并执行原子隔离及审计。任何核对、SQL、隔离错误或进程中断均不提交；不会出现已提交旧业务状态再补做隔离的窗口。

最新检查点与备份任一表不一致时拒绝恢复，包括撤销事实、防重放、预算及监控等变化。没有忽略检查点的降级参数。应准备最新一致备份；旧备份的数据取回与差异合并需要另行审查的隔离流程，不能为图方便固定旧见证或删除新见证。

成功仅输出 `{"result":"quarantined","authenticationEnabled":false}`。随后需由运维捕获隔离后的新检查点、独立保管并按原有受控恢复流程接管部署、核对账号与权限、批准新根和新密钥。普通run不会自动成为灾备恢复编排器。

<a id="drill"></a>
## 演练验证

```sh
python3 scripts/test-backup.py
python3 scripts/security-acceptance.py
```

脚本创建新的临时容器与测试库，使用真实pg_dump、pg_restore、psql；不覆盖localhost演示数据。专用用例先签发并启用密钥，确认真实HMAC认证成功，再覆盖：

1. 快照已捕获、pg_dump未导入时并发撤销，备份仍对应同一快照。
2. 撤销后独立最新检查点拒绝撤销前旧备份，目标库未改变。
3. 签名合法但表摘要不符的故障注入，整个还原事务回滚，目标仍为空。
4. 损坏、截断、追加数据及错误解密密钥被拒绝。
5. 撤销后的新备份恢复隔离，真实HMAC认证拒绝旧密钥。
6. 测试中强行重开客户端和基础根，旧密钥仍被拒绝；compromised终态不能改回active。
7. 即使测试故意指定旧见证，隔离也作废旧备份全部密钥，不把它当作业务恢复。
8. 非空目标库拒绝覆盖，目录同步失败不能推进最新见证。

完整开发安全验收新增恢复演练，共16项；通过仍不代表生产灾备或多中心验收完成。

## 本机配置

当前开发域已启用用户级LaunchAgent `com.ex-business.keygate-backup`：15分钟备份、60秒检查点。配置与加密备份在 `~/.local/share/ex-keygate/backup/`，独立检查点在 `~/.local/share/ex-keygate/checkpoints/`，日志在backup/logs，权限按私有目录管理。PostgreSQL客户端通过本机固定命名卷容器执行，包装脚本仅传递环境变量名，不暴露密码参数。

```sh
launchctl print gui/$(id -u)/com.ex-business.keygate-backup
launchctl bootout gui/$(id -u)/com.ex-business.keygate-backup
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.ex-business.keygate-backup.plist
launchctl kickstart gui/$(id -u)/com.ex-business.keygate-backup
```

这是本机开发配置，两个目录仍在同一台机器上。源数据库端口或配置改变、Docker不可用、未知schema升级时任务应失败并告警，不自动猜测其他数据库。升级时先停备份进程，审核新二进制、配置及权限，再恢复任务；不可删除尚未确认无进程使用的锁。

<a id="limits"></a>
## 限制与后续

尚未提供WAL归档/PITR、异机不可变对象存储、自动保留清理、生产RTO/RPO承诺或恢复后自动放量。最新检查点覆盖完整安全状态，在线变化会让旧备份被拒绝；不能把15分钟间隔当成已达到15分钟RPO。

SQL还原核对采用单表规范化JSON聚合；超出PostgreSQL单值或内存限制将失败回滚，不能跳过核对继续恢复。生产规模应补流式/PITR方案和容量验收。

【涉及其他业务】既有隔离恢复现在永久作废全部旧客户端根和旧密钥，手工keygate-ops隔离也遵循这一规则。原管理域数据保留，但旧密钥不能恢复使用，必须准备新根与新版本。认证中间件、在线鉴权路径和正常备份源数据未改变；审批、告警、配置升级及隔离恢复均需随本批回归。
