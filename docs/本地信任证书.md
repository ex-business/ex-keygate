# 本地开发信任证书

控制台与模拟 SSO 支持 `-tls-dir`：目录中提供 `cert.pem`、`key.pem`、`ca.pem`。目录权限必须为0700，私钥为0600的普通文件，拒绝符号链接。启动时检查证书链、期限、服务端用途及 localhost/127.0.0.1 名称；显式配置无效时停止启动，不回退或关闭TLS校验。不传参数仍使用原有临时开发证书。

本机可使用已安装的 mkcert 开发 CA：

```sh
mkcert -install
mkdir -p data/local-tls
chmod 700 data/local-tls
mkcert -cert-file data/local-tls/cert.pem -key-file data/local-tls/key.pem localhost 127.0.0.1 ::1
cp "$(mkcert -CAROOT)/rootCA.pem" data/local-tls/ca.pem
chmod 600 data/local-tls/*.pem
```

只复制公开的 rootCA.pem，不能复制或分享 rootCA-key.pem。证书与私钥放在忽略版本控制的私有 data 目录，不提交Git。本地CA只用于开发，不用于公网生产服务。

两个面向浏览器的入口必须同时使用受信证书，避免在SSO跳转后再次遇到证书拦截：

```sh
go run ./cmd/mock-sso -redirect https://localhost:18761/auth/callback -tls-dir data/local-tls
KEYGATE_ENV=development KEYGATE_ROOT_MODE=development_software \
  go run ./cmd/keygate-dev -enable-key-flow -mfa-config-file data/dev-mfa-plan.json -tls-dir data/local-tls
```

修改证书后先重启模拟SSO，再重启控制台，让控制台读取新的固定CA；两者继续使用TLS1.3及专用CA校验，不设置 InsecureSkipVerify。既有开发启动参数（如第三方插件配置）仍按原设置追加。开发控制台重启会创建新的模拟安全域，不保留旧演示会话。

当前本机已有受系统信任的mkcert CA。本次验收使用真实Chromium且 `ignoreHTTPSErrors=false`，覆盖控制台、模拟SSO、本人TOTP及两名人员依次审批后执行；不以手动忽略证书错误作为通过依据。Firefox的独立信任库未验收。
