# 管理登录与会话

## 持久化基线

登录事务与管理会话使用 PostgreSQL 权威存储，不依赖应用节点内存。

- 登录 state、浏览器绑定及会话 token 只保存 SHA-256 摘要，原始随机值不得写入日志。
- PKCE verifier 必须先以根密钥保护并绑定登录事务作用域；数据库只保存密文。存储接口本身不替调用方加密。
- 登录事务固定安全配置摘要，五分钟有效。浏览器绑定、配置摘要及数据库有效期均匹配时才能原子消费。
- 消费登录事务和审计同事务提交；数据库错误或结果不明不返回 verifier。不能重复使用已消费事务。
- 只有验证后的 OIDC 身份可创建会话；存储接口的身份是可信服务端输入，不从请求直接采用。
- 会话使用独立随机 token，数据库只保存摘要；绝对有效期至多为最近身份认证后五分钟，且不超过数据库当前时间后五分钟。
- 每次会话查询检查数据库撤销及过期状态。退出撤销与审计同事务完成，审计失败不能声称退出成功。
- 会话只代表已认证身份，不自动获得管理员或审批权限。业务接口仍需查询当前权限，不能使用测试身份名称决定角色。

## 当前范围

持久化及浏览器 Cookie、OAuth 回调、会话 HTTP 处理器已实现并通过集成测试。开发入口已装配，见《开发登录运行》；本地权限检查仍待后续接入，默认主服务仍不开放这些接口。

数据库是本阶段权威信任边界，写权限失陷可能伪造状态；目前不宣称数据库记录防篡改，也不宣称完成生产权限、独立审计或灾备恢复验收。

## 浏览器处理器

已实现开发/测试处理器并由 `cmd/keygate-dev` 显式装配；生产构造被拒绝：

| 接口 | 行为 |
| --- | --- |
| GET /auth/login | 创建浏览器绑定事务，将加密 PKCE verifier 持久化，跳转固定 SSO |
| GET /auth/callback | 校验 state 与浏览器 Cookie、原子消费事务、PKCE 换码、验证 ID Token、创建会话 |
| GET /auth/session | 查询当前会话身份、过期时间及 CSRF 值；不授予本地权限 |
| POST /auth/logout | 检查精确 Origin、会话及 X-CSRF-Token，持久撤销后清理 Cookie |

Cookie 使用 `__Host-` 前缀、Secure、HttpOnly、Path=/ 且不设置 Domain。登录事务 Cookie 为 SameSite=Lax，以允许 IdP 顶层 GET 回调；会话 Cookie 为 SameSite=Strict。回调成功返回第一方确认页，再由用户点击查看会话，避免在跨站重定向链中丢失 Strict Cookie。

仅接受直接 HTTPS 和配置的 Host，不信任任意代理头。SSO 端点固定为 HTTPS 且与 issuer 同主机；不接受调用方自定义跳转地址。配置版本、目标 IdP、客户端、回调及根版本共同绑定登录事务，安全配置变更须提高 PolicyVersion 并保持节点一致。

使用单独的随机 state、浏览器绑定、nonce、verifier 及会话 token。PKCE verifier 先持久预留根密钥预算再加密，回调通过已消费事务建立可信解密作用域。数据库错误、加密失败、无效 Token 均不签发会话，不将 ID Token 当作 API Bearer。

CSRF 值由会话秘密通过固定用途 HMAC 派生，仅同源会话接口返回；退出必须同时匹配 Origin 与 CSRF 请求头。浏览器不需要读取 HttpOnly 会话 Cookie。

已通过真实 PostgreSQL + 临时 TLS 模拟 SSO 的完整流程测试，包括授权码换取、三方身份校验、浏览器绑定、配置摘要、回调并发一次消费、重复/伪造 state、重复 Cookie、密文损坏、过期、退出 CSRF 和撤销拒绝。真实浏览器 SameSite 行为及真实 IdP 仍需后续验收。

开发 SSO 与控制台应使用不同主机名，例如 SSO 使用 127.0.0.1、控制台使用 localhost；Cookie 按主机而非端口隔离，不把不同端口视为 Cookie 安全边界。

会话查询和撤销同样绑定固定认证配置摘要，不能在切换 issuer、客户端、回调、策略版本或根版本后沿用旧配置的会话。迁移时为历史无绑定记录设置失效占位值并立即撤销，避免兼容路径恢复旧权限。
