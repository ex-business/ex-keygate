# ExKeyGate 分阶段实施计划

日期：2026-10-19

## 实施原则

以《功能设计》为需求基线，分阶段实现、验证和记录结果。企业级安全是待验收目标，不代表当前实现已满足。安全控制随对应功能实现，不延迟到最后补做。未实现能力明确不可用，不以成功占位响应替代。

## 阶段 1 必须明确的决策

1. 已确认覆盖受控后端、桌面、移动端和浏览器，分别配置策略；仍需确定每类认证协议及密钥保护方式，不让客户端自行选择更弱策略。
2. 基础密钥的用途和保护方式，以及首期 Bearer、HMAC 或非对称认证的选择。
3. 管理及审批人员身份来源、多因素认证方式、授权人数阈值与初始化流程。
4. 持久化设施、密钥加密密钥托管方式和防重放一致性方案；不自行连接现有业务数据库。
5. 首期第三方厂商、运行环境和容量；跨数据中心是否仅预留。

目前这些决策未全部确认，不将某种客户端信任模型默认为既定需求。Go 实现及一个工程已确定；多人授权暂按 M/N 审批设计，密码学门限密钥不在当前范围。

## 工作与验证规则

- 每阶段维护实际完成项、验证命令、结果、剩余风险和下一阶段依赖。
- 核心测试覆盖拒绝路径、权限边界、事务竞争、超时、重试、回滚与恢复，不仅验证成功路径。
- 不在测试、文档、日志或 Git 中保存真实凭据。
- 每次 commit、push 或 PR 前执行独立审查；按用户授权逐点使用英文提交；不推送或发布。
- 新项目使用独立仓库及 `codex/keygate-initial` 分支；尚无远程及历史基线，后续并行会话必须使用独立 worktree。

## 影响范围

当前仅创建独立工程和设计文档，未修改现有项目及 base 公共代码，未部署服务或连接现有基础设施。

【其他业务影响待确认】后续客户端、第三方及身份系统集成的调用链和回归范围尚未确定，未执行跨业务验证。
