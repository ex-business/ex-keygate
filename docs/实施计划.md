## 实施原则

以《功能设计》为需求基线，分阶段实现、验证和记录结果。企业级安全是待验收目标，不代表当前实现已满足。安全控制随对应功能实现，不延迟到最后补做。未实现能力明确不可用，不以成功占位响应替代。

后续实施以[待完善功能清单](待完善功能清单.md)中的 KG-01 至 KG-11 为准，优先补齐证书详情、历史版本、续期与提醒。下列分阶段表保留原实施基线，不代替最新完成状态。

## 阶段 3 下一批实施点

本批已按以下顺序实现并验证，实际接口、固定开发限制和操作步骤见[生命周期运行手册](生命周期运行手册.md)。用户指定顺序为：轮换 → 撤销 → 异常恢复 → 审计查询与导出；人员/策略在线管理不在此批前置扩大。规则分别见《功能设计》的[轮换](功能设计.md#rotation)、[撤销](功能设计.md#revocation)、[恢复](功能设计.md#recovery)和[审计](功能设计.md#audit)。

| 小点 | 复用已有能力 | 本批已实现交付 | 核心验收 |
| --- | --- | --- | --- |
| 3.1 轮换管理 | 新版本、领取/持有证明、审批激活、active/retiring 唯一性、数据库时间失效 | 轮换任务及关联视图、到期提醒、收尾、原有效期与退役信息追踪 | 提醒不绕过批准；两版过渡正确；收尾任务停机也拒绝过期旧版；失败不复活旧版 |
| 3.2 泄露撤销 | 正常 key_disable、客户端应急停用、认证同库状态检查 | 按版本 compromised 终态、根关联阻断、事件/原因、撤销事实与恢复约束 | 减权立即生效；原版本永久拒绝；不能用重包裹替代泄露换钥；旧票及晚到响应无效 |
| 3.3 异常恢复 | 本地事务回滚、幂等记录、最终资格/修订复查、预算只增、一次领取 | 恢复任务及证据、分类核对、停用客户端的隔离换钥与原子恢复、重启/备份隔离校验；远程 UNKNOWN/隔离接口已预留，实际远程执行暂不装配 | 故障注入不重复执行、不重发秘密、不重置预算；准备时认证关闭，最终独立审批原子恢复且旧版本不复活；无可信校验点不恢复授权 |
| 3.4 审计产品能力 | audit_events、关键变更同事务留痕、受控日志 | auditor 范围查询/页面、快照导出、认证失败聚合、可靠 outbox/独立归档及完整性校验 | 越范围/撤权后访问拒绝；无敏感材料；写审计故障回滚；归档幂等与篡改检测通过 |

每个小点形成可审查的独立提交；只读查询、状态变更、迁移及界面可按实际依赖进一步拆分。先核对模型与迁移，再做处理器及权限，最后补故障/竞争测试与文档，不以一次大提交掩盖未验收路径。

### 共同约束

- 沿用环境/客户端隔离、自然人去重、当前权限和目标修订复查；不增加万能恢复 Token、临时降阈值或明文导出。
- compromised 已实现终态撤销；本地恢复、审计查询和签名归档已交付。UNKNOWN 的远程查询及 fencing 仅预留接口，不能冒充已有远程执行器。
- 敏感变更和认证成功已与本地审计/outbox 同事务。外部归档和通知不在长数据库事务中等待。未经可靠本地留痕不报告变更成功，外部认证始终失败关闭。
- 每个敏感变更保留幂等操作身份、原批准清单及结果。恢复方案改变权限/信任时重新审批；旧批准不能批准新恢复方案。
- 撤销、审批/执行、防重放和根预算的恢复保护必须依赖备份之外的可信校验点；没有这些条件就不交付生产恢复入口。
- 开发过渡期上限仍为十五分钟；生产轮换周期、提醒时间、审计留存/导出上限、外部告警接收方、归档存储及 RTO/RPO 需受控配置或环境确认。不创建外部通知或自动执行需审批的业务操作；服务内每分钟仅收尾已按数据库时间失效的版本与轮换。

### 验证与环境

自动化测试继续使用独立临时 PostgreSQL，覆盖并发投票/执行/撤销、时间边界、领取消费、进程崩溃、提交结果未知、备份回滚和归档失败。真实 Provider、生产根及灾备演练无法用软件模拟测试代替；未完成的环境依赖逐项保留，不伪造 PASS。

## 阶段 1 必须明确的决策

1. 已确认覆盖受控后端、桌面、移动端和浏览器，分别配置策略；后端固定 HMAC 请求签名已开发验证，原生端 OIDC/PKCE 与浏览器 BFF 为设计路径，其完整业务认证仍待实现。
2. 已确定基础 KEK 保护客户端密钥、用途隔离；后端选固定 RFC 9421 HMAC Profile，软件根只用于开发，生产根仍待接入。
3. 管理与审批采用 OIDC/SSO，目前用本机模拟；真实多因素映射、人数阈值与初始化流程仍需确定。
4. 已选择 PostgreSQL 权威存储并验证基础原子操作；软件根只用于开发测试，生产前接 KMS/HSM，不连接现有业务数据库。
5. 首期第三方厂商、运行环境和容量；跨数据中心是否仅预留。

目前这些决策未全部确认，不将某种客户端信任模型默认为既定需求。Go 实现及一个工程已确定；多人授权暂按 M/N 审批设计，密码学门限密钥不在当前范围。

## 工作与验证规则

- 每阶段维护实际完成项、验证命令、结果、剩余风险和下一阶段依赖。
- 核心测试覆盖拒绝路径、权限边界、事务竞争、超时、重试、回滚与恢复，不仅验证成功路径。
- 不在测试、文档、日志或 Git 中保存真实凭据。
- 每次 commit、push 或 PR 前执行独立审查；按最新全局规范逐点使用中文提交，推送/合并按用户授权执行，不部署生产。
- 当前独立仓库为 ex-business/ex-keygate；新功能从确认的最新基线建立独立功能分支，继续既有功能复用对应空闲分支；并行写入会话必须使用独立 worktree。
