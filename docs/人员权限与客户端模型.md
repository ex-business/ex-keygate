# 人员权限与客户端模型实施

本批新增 `internal/access` 领域模型和 `storage.DevelopmentControl`，只允许开发/测试构造，不开放生产管理权限或 HTTP 调试入口。旧审批存储不是此授权流程的入口。

- 外部身份摘要与现有 OIDC 的 issuer/sub 算法一致；本地自然人映射独立管理，不通过邮箱或昵称判断同一人。
- viewer、requester、approver、policy_admin、auditor、emergency_operator 分开存储。范围为当前环境全部客户端或指定 clientId，不向人员发放 executor_service 角色。
- 每次读取使用固定登录 Profile 的有效会话和当前人员/授权，不缓存角色。敏感操作按数据库时间核对最近五分钟的原始认证时间；模拟身份只用于开发。
- Profile 按后端、桌面、移动、浏览器独立配置。首期后端允许内部软件 HMAC，公开客户端使用联邦会话；原生共享秘密和占位硬件能力保持拒绝。
- 认证 Profile 版本和客户端类型通过带环境复合外键约束。客户端创建将只允许后续获批执行路径调用，不新增直接绕过审批的 CRUD。
- 安全域控制行将同域撤权、审批与执行串行化。当前实现优先验证正确性，不宣称达到多中心写入吞吐要求。

## 离线初始化

`BootstrapOffline` 是受控进程内接口，不是公网接口。配置需包含至少两名不同自然人的核验负责人和外部确认记录摘要；软件仅检查配置一致性，不能证明实际完成了人工核验。初始化原子写入人员、授权、Profile、审批池和审计；唯一安全域哨兵不因停用人员而消失。

不会自动将模拟 SSO 用户加入权限。实际组织身份、核验材料与生产初始化流程仍需单独接入。

## 迁移和验证

授权表使用独立的编号 1 SQL 迁移，保存文件 SHA-256 校验和，已有迁移内容变化拒绝继续。迁移只通过显式 `storage.Migrate` 执行；不由普通请求执行。不重写旧开发审批或继承旧票。

验证使用新建、隔离的临时 PostgreSQL，检查重复初始化、同人多账号审批池、登录 Profile 隔离、无权限与越范围访问、撤权立即生效、生产模式拒绝以及迁移校验和保护。本批不连接或修改现有业务数据库。
