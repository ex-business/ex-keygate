# PostgreSQL 共享安全状态

本阶段实现共享防重放原子记录、基础密钥包装预算及事务内审计，不包括完整数据库高可用拓扑、认证服务或审批事务。

## 存储决策

采用 PostgreSQL 作为首期安全关键状态的权威持久化设施，避免进程内缓存决定防重放或根密钥用量。运行实例必须连接同一个权威写入集群，不能将异步只读副本用于安全判定。真实部署地址与凭据待环境配置，不连接现有业务库。

`storage.Migrate` 为显式迁移入口，创建独立 `keygate` schema；不由请求自动执行。生产必须分别配置迁移身份和最小权限运行身份，不能把测试容器的超级用户用法复制到生产。

## 防重放

- 作用域包含环境、客户端、密钥和版本，nonce 要求 32 字节。
- 数据库存储作用域与 nonce 的 SHA-256 摘要，唯一约束决定并发请求只有一次被接受。
- 有效截止时间须晚于数据库当前时间且不超过未来五分钟。
- 本接口不验证签名；调用方先验证签名、受众、身份和签名时间，再消费 nonce。
- 截止时间由服务端按完整请求接受窗口推导，包含允许的时钟偏差，不能由客户端独立指定；达到截止时间后即不再接受原请求，避免记录被清理但请求仍有效。
- 数据库失败或结果不明确时拒绝，不允许因为写入报错而放行。
- 过期清理不代替签名时间校验，不能让已过期请求在删除记录后再次通过。

## 基础密钥用量

- 每个不可变 rootID 单独注册上限，最大 2^30，低于随机 nonce 的每密钥使用数量上限。
- 使用原子条件更新预留一次用量，并在同一事务插入审计事件，任何一步失败均不返回许可。
- 预留提交成功后才能调用加密；加密失败或结果不明不退还额度。
- 重复注册不重置已用计数，不提供提高上限或清零接口。
- 所有使用同一实际根密钥的节点、环境及其他程序必须共用预算，不能用不同 rootID 重复注册同一实际根密钥。代码目前不能从外部托管系统证明这一约束，生产托管集成前必须落实。
- 恢复旧备份可能回退计数，恢复流程应隔离旧根密钥的新增加密用途并启用新根版本，不能直接恢复业务；本阶段尚未实现恢复控制器。

## 审计边界

当前审计与对应预算变更同事务提交，包含事件、请求、操作人、动作、目标和结果，不保存任意请求体或密钥。字段接受受限标识，不接受秘密内容。

数据库管理员仍能修改数据库，当前表不构成防篡改归档。运行角色的表权限、独立归档、告警和留存策略尚待部署阶段落实。传入 Audit 的 actor 必须由可信身份层提供，本存储包本身不提供认证或审批。

## 验证方式

运行 `python3 scripts/test-postgres.py`：创建独立 PostgreSQL 16 测试容器、随机密码、随机本机端口；运行真实数据库及 race 测试；结束后删除容器。不复用业务容器、数据库或凭据。

已验证：两个 Store 对象竞争同一 nonce 只有一个接受、客户端隔离、无效时间拒绝、两个节点并发预留不超预算、审计插入失败导致预算回滚。尚未验证真实跨机网络分区、数据库主备切换和灾备恢复。
