# 审批持久化

当前实现申请创建、投票和查询的 PostgreSQL 持久化；尚未接入管理身份认证、现行策略与人员撤权查询、取消/执行日志或 HTTP 接口，不可作为完整授权服务开放。

## 规则

- 创建时只接受有效的新申请，固定操作与策略快照；与创建审计同事务提交。
- 使用数据库时间检查有效性，投票时间由数据库产生。
- 投票必须携带审批人实际查看的操作摘要，摘要不一致拒绝。
- 每个申请通过行锁串行化跨节点写入，重复身份不重复计票。
- 申请人不能投票，授权名单之外的身份不能投票；至少两名独立授权人同意。
- 拒绝后不继续收集投票，达到阈值后不再改变批准内容。
- 投票写入与审计同事务提交，审计失败回滚投票；提交结果未知不向调用方返回成功。
- 查询通过初始快照和投票记录重放领域规则，校验投票顺序、重复身份及修订号，不直接信任存储的“已批准”布尔值。

## 安全边界

持久化包仍不是身份认证或权限层。传入身份、策略必须来自可信服务端；调用方必须检查当前身份与权限。执行前还必须重新核对现行策略、人员有效性、目标版本及审批有效期，并将执行占用和审计原子提交。

当前未实现执行器，因此不会依据持久化批准结果产生真实密钥操作。领域对象已经分离审批结果与执行结果；后续必须增加持久执行日志，不能从投票推断某个外部操作已经执行成功。

数据库被控制后仍可能伪造记录，投票重放不等于防篡改或密码学门限授权；独立审计与硬件/独立执行边界仍需后续落实。

## 验证

真实临时 PostgreSQL 下两个 Store 并发提交同一审批人的 16 次投票，只有一票成功；第二位审批人投票后达标；错误摘要拒绝；审计冲突时申请修订号和票数均回滚。领域测试验证快照恢复、重复身份拒绝和倒序时间拒绝。
