# ExKeyGate

支持插件扩展、共享密钥管理和多人授权的认证服务，采用 Go 单工程。

已接通开发后端流程：客户端管理 → 密钥申请 → 多人审批 → 启用 → 实际请求认证 → 停用。开发控制台在显式开启后提供管理页面、HTTP API 和接收方 CLI；启用前认证拒绝、启用后成功、停用后立即拒绝。默认主服务仍只提供存活检查，不用于生产。详见 [实施进度](docs/实施进度.md)。

工具链：Go 1.26.9（由 go.mod 固定，启用自动工具链时首次运行可能下载）。

运行：`go run ./cmd/keygate`。进程存活检查：`GET http://127.0.0.1:18760/health/live`。该接口不表示业务就绪，不得作为认证能力验收依据。

实施顺序与门禁见 [实施计划](docs/实施计划.md)，功能要求见 [功能设计](docs/功能设计.md)。

正式 module 路径待仓库地址确定后设置。禁止提交真实密钥或环境凭据。

数据库集成测试：`python3 scripts/test-postgres.py`，需要 Docker；使用独立临时容器并在结束后清理。普通 `go test ./...` 未配置专用测试数据库时会跳过数据库集成用例。

本机模拟 SSO：`go run ./cmd/mock-sso`，仅开发测试使用，见 [模拟 SSO](docs/模拟SSO.md)。测试身份不代表真实多因素认证。

开发登录闭环：[启动与验证](docs/开发登录运行.md)。可运行 `cmd/keygate-dev` 对接本机模拟 SSO，验证持久化登录和退出；默认 `cmd/keygate` 仍只提供存活检查。

开发内核说明：[人员权限与客户端模型](docs/人员权限与客户端模型.md)、[审批执行](docs/审批执行闭环.md)、[软件密钥操作](docs/软件密钥操作闭环.md)。

完整流程：`KEYGATE_ENV=development KEYGATE_ROOT_MODE=development_software go run ./cmd/keygate-dev -enable-key-flow`，进入 `https://localhost:18761/manage`。申请人为 `demo-requester`，审批人为 `demo-approver-1` 和 `demo-approver-2`，使用独立会话。模拟账号不等于真实多人身份。接收方通过 `cmd/keygate-client` 生成公开配置、加密领取和签名认证，步骤见 [HTTP 流程与接收方命令](docs/客户端密钥HTTP流程.md)。


生命周期：开发模式已支持轮换任务与提示、泄露撤销、两阶段隔离恢复、审计筛选/JSONL 快照、独立签名归档及离线备份状态核验。操作步骤见[生命周期运行手册](docs/生命周期运行手册.md)。KMS/HSM 保留接口，真实接入延后；这些开发能力不等于生产安全认证或多中心验收。

插件管理：内部实现的启停与修订绑定、通用 HTTPS/mTLS 核验适配器、本机模拟插件和管理页面已接入开发模式，见[插件管理](docs/插件管理.md)。硬件、KMS/HSM 保留接口；第三方公开向量自检不代表真实客户端认证已接入。

多节点：应用可同时使用共享权威 PostgreSQL，新增节点租约、代次隔离、就绪探针与双进程故障验收。可信装配及边界见[多节点与安全验收](docs/多节点与安全验收.md)；运行 `python3 scripts/security-acceptance.py` 获取开发验收报告，生产门禁单独标记。

H5：新增浏览器客户端联合身份会话执行器、同源 TypeScript/ESM SDK 和 `/h5` 演示。登录、认证、退出及停用闭环见[H5 认证与 SDK](docs/H5认证与SDK.md)。移动端与桌面端按本期范围暂缓。

原生二次验证与逐人 M-of-N：邮件、短信、TOTP、硬件插件和不同自然人依次确认交接，详见[原生MFA与人员流转](docs/原生MFA与人员流转.md)。未配置插件不放行。

运营管理后台：分区导航、表单操作、逐人审批详情和桌面/窄屏适配，见[运营管理后台](docs/运营管理后台.md)。

账号密码登录：独立登录页、本地密码 + 原生二次验证、保留 SSO，见[账号密码登录](docs/账号密码登录.md)。
